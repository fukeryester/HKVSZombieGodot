# 游戏配置

六份 Excel 是唯一编辑入口。按“所属对象”筛选，修改黄色的 C 列；A/B/D/E 是对象、字段、类型及说明，F 列是不可改的唯一 ID。支持整行排序。不要删除行、复制出重复 ID 或填公式。

| 表 | 配置内容 |
|---|---|
| 文明 | 名称、描述、图标、配色、基地名称与生命、初始人口、采集和回复、农民、文明特性、三个技能槽 |
| 兵种 | 名称、描述、图标、唯一的解锁时代、最终生命/伤害/速度/训练时间/人口、四资源造价、显示体型、特殊能力 |
| 技能 | 名称、描述、图标、解锁时代、最终冷却、能量消耗、效果时间/比例/数量、召唤兵种 |
| 建筑经济 | 通用建筑名称/描述/图标/四资源成本/时间/人口、升至二三四本的资源/时间/基地增血、农民、队列、开局资源、拆除返还 |
| 战争巨兽 | 名称、描述、图标、生命、伤害、范围、速度、攻击间隔、触发比例与登场清兵范围 |
| 战场布局 | 唯一的战线长度、两边基地留白、同队基地间隔、出生位置和画面投影 |

只保留最终生效值。兵种的 `art.tier`、前置科技和初始化时代倍率不再另列；修改兵种时代时，解锁科技和美术时代自动一致。四资源价格直接生效，不再反算旧金币成本。兵种“战斗价值”仍单独保留，因为它用于技能选目标、击杀能量及战绩，不是购买价格。文明质量/训练折扣等初始化中间倍率已折算在各兵种最终数值内，不再提供第二入口。

升本相关项只在“建筑经济”的“升至2/3/4本”各出现一次。民房人口为“提供人口”，兵种和农民人口为占用量。文明农民价格倍率只影响农民；士兵直接读取自己的四资源价格。技能冷却填最终秒数，不会再次乘 0.65。描述是可编辑文案，调整数值后应相应更新描述。

## 图标和技能引用

- 独立图标：`assets/icons/my_unit.png`。先将 PNG/WebP/JPG/SVG 放入项目 assets 目录，再填路径。
- 使用已有图集：`assets/sprites/hk_finance.png#0,0,7,12`，表示行、帧、总行数、总帧数，行与帧从 0 开始。内置角色图集使用已校准的透明边界裁切。空图标表示不显示。
- 文明图标用于文明选择；兵种图标用于训练按钮和图鉴；技能图标用于施放按钮；建筑与巨兽图标用于建造/选择界面。图标不替换战场动画图集。
- 技能槽填写技能 ID，例如 `capital_injection`，对应技能表唯一 ID 中 `SKILLS.capital_injection.name` 的中间部分。三个槽均要求有效、同阵营技能。
- 辅助类型使用 `heal`（治疗）或 `convert`（转化）；布尔值使用 Excel 的 TRUE/FALSE。

## 导入与验证

运行 `npm run config:import`，然后重新构建游戏。`node tools/build.mjs all` 会自动导入。玩家运行时不需要 Excel/Python，启动时只安装一次已编译的最终配置。

导入检查字段类型、重复/缺失 ID、时代范围、图标文件和图集坐标、技能引用、基地位置。失败时不写入运行文件。原始 `runtime/core` 保留校验，生成文件位于 `runtime/configured` 与 `runtime/tuning.js`，不要手改。`tools/config-schema.mjs` / `tools/sheets/create-config.mjs` 仅供开发者迁移表结构，会重建初始值，日常改表不要运行。

“高级规则”已删除：数组索引、随机数种子常量、固定步长、重复初始化过程不属于策划表。复杂效果采用具名绑定，一个字段可以供多个内部用点共享，不再要求策划修改源码位置。

玩法配置哈希用于联机与回放版本检查。文案、配色和图标变化不改变玩法哈希；数值、时代、技能槽修改需要双方使用同一版本。旧表已备份在本机 artifacts/config-v1-backup，Git 历史也保留原文件。
